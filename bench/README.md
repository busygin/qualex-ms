# Benchmark tooling

The means to rerun the experiments behind `benchmarks.md` and the experimental
switches in `main.cc`.  It lives in the repository because the machine the
experiments run on reboots and clears `/tmp`; every step here picks up where it
stopped when the same command is run again.

## Suites

| suite | graphs |
|-------|--------|
| `dimacs` | the 70 DIMACS graphs outside the ten big ones (`lists/dimacs.lst`) |
| `dimacs-big` | the ten big ones (`lists/dimacs_big.lst`) |
| `ru`, `rw` | the 120 uniform random graphs with n <= 1000, unweighted and weighted |
| `ru2000`, `rw2000` | the 12 uniform random graphs with n = 2000 |

DIMACS graphs are read from `$QMS_DIMACS` (default `~/DIMACS`).  The random
graphs are generated by `tools/random_graphs.py` into `graphs/rnd` on first
use, and come out identical every time with numpy 2.3.5.

## Running

    bench/run.sh -j 6 dimacs,ru,rw head,ancw

builds the solver and runs every listed variant on every graph of the listed
suites, with 6 workers taking turns on the GPUs, skipping what is already
recorded.  A long run survives a closed terminal with

    nohup bench/run.sh dimacs,ru,rw head,lzw > bench/runs/nohup.log 2>&1 &

A variant is a name and the environment the solver runs with, one line in
`variants`, which holds every variant of the perturbation, anchoring and
lambda_max experiments so far; a new experiment is a new line.

## Results

Each build of the solver gets its own directory, `runs/bin-<sha1 of the
binary>/`, so results of different code never mix, and head needs running
once per build:

    res/<suite>/<variant>.<worker>.res   graph, value, seconds    committed
    SOURCE                               git describe and date    committed
    log/<suite>/<variant>/<graph>.out    solver output            ignored
    work/<suite>/<variant>/<graph>.sol   the clique found         ignored
    bin/qms                              the binary               ignored

## Comparing

    bench/compare.py rw head,ancw,lzw --pairs ancw:lzw --diag --moves

reports, over the graphs every variant has finished, how many reach the
reference, the mean gap to it, the time, and wins and losses against the
baseline (head), split by density on the random graphs.  When head is listed it
is checked against `benchmarks.md`, which also shows that a regenerated graph
set is the one benchmarked.  `--diag` summarizes the diagnostic lines of
`QMS_STATS` and `--moves` how far improved cliques moved from the baseline's.

## Optima

    bench/cliquer.sh -j 8 rw

proves optima of the random graphs with cliquer into `optima/w.tsv` (`u.tsv`
for the unweighted suites), which `compare.py` then takes as references.  The
optima behind `benchmarks.md` were lost with `/tmp` and have to be recomputed
this way; the slowest of them needed 47 minutes.

## Checking an idea in numpy

`wrapper.py` has dense numpy versions of the wrapper constructions in `main.cc`
(anchoring, the literal Lovasz step, the projection and the gauge-invariant
spread) to import, and as a script summarizes them for one graph:

    bench/wrapper.py ~/DIMACS/gen400_p0.9_55.clq.b \
        -q bench/runs/bin-*/work/dimacs/head/gen400_p0.9_55.sol
